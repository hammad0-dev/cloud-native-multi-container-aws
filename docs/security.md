# Security decisions and limits

Passwords use Werkzeug's maintained scrypt hashing. ORM queries bind parameters. All browser mutations use CSRF tokens; document lookups include authenticated owner ID and return 404 for other owners. Sessions are HTTP-only, SameSite=Lax, expire after 30 minutes and default to Secure cookies. Login and registration are limited in memory. The Nginx address is the observed remote address, so limits conservatively share a proxy-wide budget per worker; they are not reliable distributed brute-force protection and reset on restart. Use a shared limiter/WAF and trusted proxy configuration for a larger system.

Only nonempty valid UTF-8 `.txt` documents are accepted. Control bytes other than tab/newline/carriage return are rejected; browser content type is ignored. Display names use Werkzeug normalization and objects use random UUID keys. Downloads stream through an authorized app request as text attachments with nosniff, no-store and a restrictive CSP. No presigned URLs are emitted or logged. A presigned URL alternative must first authorize ownership, expire quickly, and treat the URL as a bearer credential. No malware scanning is implemented; arbitrary text can still be harmful when used elsewhere.

The app runs UID 10001, read-only, with temporary tmpfs, no Linux capabilities and no-new-privileges. Nginx uses UID 101 and port 8080. This configuration passed local container health checks and an HTTP smoke test on Docker Desktop. Explicit image versions are not immutable digests; record release digests and scan dependencies/images before cloud use.

Compose file-backed secrets mount under `/run/secrets`; this is not Docker Swarm's encrypted secret store. Ordinary Compose does not encrypt host secret files at rest. EC2 EBS encryption helps against detached-disk exposure, not a compromised root account. Runtime retrieval uses the EC2 role, writes files owned by UID 10001 with mode 0400 in a root-owned 0700 directory, and avoids environment passwords/command-line values. Host root and the container process can read secrets. File bind mounts retain old inodes after atomic replacement: recreate containers after refresh. Do not print `docker compose exec env`, database URLs or secret responses. Development files are readable for container interoperability inside a 0700 parent; restrict Windows ACLs separately.

RDS manages the master password in Secrets Manager. Terraform stores only secret container metadata and RDS management flags, not secret values. Bootstrap uses a separate operator profile to read master credentials and create `vault` (DML only) and `vault_migrator` (schema privileges). The runtime role cannot access the master secret or write secrets. Remove the migration password file and revoke/drop the migrator user through the operator path when no release is pending. Changing existing users should be reviewed: bootstrap rotates the migrator password.

Cloud MySQL connections require TLS with CA and hostname verification and `REQUIRE SSL` accounts. Download the official current RDS CA bundle; never bypass verification. Local MySQL explicitly disables TLS only on the private development Docker network. Runtime DB startup errors never require disabling TLS. IMDSv2 is required, with hop limit 2 for bridge-network containers to obtain instance-role credentials; all containers on this host therefore share a trust boundary. No cloud access keys are placed in Compose.

S3 blocks public access, disables ACL ownership, encrypts with SSE-S3, denies insecure transport and gives runtime only GetObject/PutObject/DeleteObject on `uploads/*`. No ListBucket, bucket administration or versioning is needed. Objects are permanently deleted unless separately backed up.

HTTP exposes credentials, cookies and file contents in transit. Temporary HTTP demos must use dummy accounts/files and explicitly set COOKIE_SECURE=false. Keep Secure cookies for HTTPS. This project does not provision HTTPS automatically; see deployment for the domain/certificate extension. There is no email verification, password reset, audit pipeline, antivirus, multi-factor login or high availability. Do not store real confidential documents in the demo.

State, plans, `.env`, secret files, private keys and uploaded data are excluded from Git. Terraform sensitive flags redact presentation but do not remove values from state. Treat local state/plans and machine backups as sensitive. Review a Git diff and secret scan before any publication.
